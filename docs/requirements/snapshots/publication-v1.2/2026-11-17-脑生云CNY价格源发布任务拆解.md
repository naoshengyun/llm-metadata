# PUB-T01：原候选到原生模型源契约

Status: ready-for-agent（范围已完整；是否可开工由Blocked by决定）

**What to build:** 维护者选择固定候选和明确子集后，获得能被固定rc50源URL抓取/预览的模型价响应；同一演示明确插件与工具需要独立入口。原产物不可覆盖；错误envelope/混币/缺价拒绝，输出有身份。

**Blocked by:** None；无票间依赖，可作为首票。

关闭条件：PUB-AC-01、PUB-AC-02、PUB-AC-03、PUB-AC-09；原固定artifact保持，发布适配success/data生成新release身份，partial/排除项/原日期可见；本地HTTP+隔离原版fetch演示通过且没有供应商/实例价格写入。模型URL不会偷偷携带插件/工具；按TDD逐行为并经独立审查。此关闭不代表公开发布。

## Seam 与可独立演示的路径

S：固定候选→显式测试selection→模型发布响应与身份；H：本地静态HTTP→固定rc50原生fetch/preview→所选mode/expr精确比较。H只读，不保存价格，不复用原I夹具。

演示：一个明确测试模型子集得到新发布身份和success/data；原版预览值与候选一致；同输入重建字节一致。去掉success由原版报错；去掉所选expr或混币由发布侧拒绝（原版不承担这项完整性保证）。旧artifact字节保持。测试selection不得叫首版可售名单。

## 关闭证据

- [ ] PUB-AC-01/02/03/09逐项给出输入身份、期望及结果；原候选hash前后相同。
- [ ] H请求记录和配置前后读回证明未保存模型/插件/工具；失败路径不会输出可提升版本。
- [ ] 报告标明partial、来源日期、全参考/排除项，且插件工具未由模型URL导入。
- [ ] 固定实现commit与独立审查结论关联；没有公网发布结论。

D2批准的资格边界：仅资料完整、固定原版可表达且经用户确认的模型子集可进入实际发布；本票使用明确测试selection验证能力，不代用户确认首发。插件/工具交付和独立接入不意味着其首发名单已获选。

# PUB-T03：受控稳定入口提升与回退

Status: ready-for-agent（范围已完整；是否可开工由Blocked by决定）

**What to build:** 审阅者确认固定版本后，在演练中手动提升发现指针与模型消费入口；提交前失败保持旧入口，提交后结果不明先读回，手动回退复用旧不可变版本，并给运营可追溯回执。

**Blocked by:** PUB-T02；前置关闭后开工。

关闭条件：PUB-AC-05、PUB-AC-06、PUB-AC-07、PUB-AC-09、PUB-AC-10；本地HTTP/平台mock验证同部署快照一致、缓存跨版本检查、提交前失败不提升/提交后unknown读回、回退身份、重复执行和权限不足失败；只手动、固定SHA动作/最小权限声明及独立QA审查通过。候选CI继续只读，继承workflow不被启用，无cron/自动上游合入；稳定入口回退不写实例。真实Pages开通/Actions新许可/部署试跑及公开下载回执在另外明确获准后验收，不在本票关闭时冒称完成。

## Seam 与可独立演示的路径

复用S/H与确定性平台mock：审阅者针对release/hash/diff确认→准备完整部署快照→本地提升发现指针和模型源→读回；再确认回退到历史版本→读回。托管方向已批准为现有组织仓库Pages，具体权限/流程设计已批准，但真实权限设置和执行仍未授权，mock通过不能当作真实Pages权限或可达性证据。

演示：版本A提升至B、回退A，历史固定文件不变；无确认、权限不足、缺分区、确认后内容变化、重复执行均有确定结果。提交前失败保留旧入口；平台提交后回执超时记unknown并先读回，不能笼统承诺所有失败都未提升。跨请求缓存读到A/B混合时，通过固定URL/hash识别并停止，不宣称公网原子读。
