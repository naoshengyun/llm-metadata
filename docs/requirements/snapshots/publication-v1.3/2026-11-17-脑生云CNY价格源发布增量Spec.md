### Problem Statement

运营已有可追溯候选和本地导入证据，但没有已确认的长期公开源、稳定版本发现、受控提升/回退及分区接入说明。短期Actions附件不是稳定价格源。

### Solution

提供由明确选择和审阅记录产生的固定版本包、稳定发现及模型消费入口；运营先预览差异再选择应用。插件与工具随同一版本包交付，按已有原生接口独立配置。发布过程不写采购渠道、别名或分组倍率。

### User Stories

1. 作为运营，我要看到版本、来源日期及选中条目，判断适用范围。
2. 作为运营，我要按固定版本URL读取模型价，避免确认期间内容变化。
3. 作为运营，我要知道哪些插件/工具需另行配置，避免漏费误成功。
4. 作为维护者，我要显式选择子集并保留排除项，避免complete=false被隐藏。
5. 作为审阅者，我要看到新旧语义diff和来源/输出hash，核对发布意图。
6. 作为维护者，我要候选通过后人工提升稳定入口，提交前失败保留旧入口、提交后未知先读回。
7. 作为维护者，我要可回退到已验版本，保留发布/回退记录。
8. 作为运营，我要将源回退与实例恢复分开，避免错误重放配置。
9. 作为维护者，我要核价与上游代码同步分开，避免自动变成最新官方价。
10. 作为安全负责人，我要发布权限独立于只读测试，避免继承上游定时路径。

### Implementation Decisions（开发设计已批准）

沿用固定候选、原价政策、native rc50和三分区契约；模型源发布适配需补齐原生success envelope，不能默改旧artifact。发布manifest覆盖原候选身份及实际HTTP输出hash，明确full/partial模式；完整包语义和来源日期保持。D3已确定人工核价PR及手动触发；具体发布环境、权限和入口设计已随B/D4方案获准开发，实现后独立审查；实际开通/许可修改/部署仍未授权。

### 发布前精确选择门禁（规则与技术记录设计已批准，具体首发名单未批准）

开发测试允许使用明确标注的测试selection，不能提升为首版名单。真实发布前须呈现同一份可核对记录：artifactId/sourceSha/适配器版本/releaseId、按模型/插件/工具列出的精确selected身份与数量、每项来源/核价日期/单位、136参考逐行去向、未选与不可表达条目的不同原因、141差5注记、输出inventory/hash、新旧语义diff、确认者及批准记录。任何选择、字节或来源改变都使此前确认失效；测试四项和53候选不自动获选。

完整参考行、官方价目条目、原生模型键、插件项和工具项是不同计数单位，不要求它们数字相等，不把重复协议行合并丢弃。可表达但未获选条目应标为未选，不伪装成缺价；原候选excluded不删改，发布选择另记。partial只表示公开交付的选择范围，原完整包complete=false原样可见；不代表可售批准。

### Testing Decisions（已作为开发依据）

复用S：固定产物/schema/语义diff、拒覆写与负例；现有官方快照和CI包完整性测试可提供先例。**新增H**：本地静态HTTP fixture下载固定版/稳定入口并由隔离原版rc50的上游fetch/preview路径读取，验证源URL与完整envelope；这不是供应商调用，也不是旧I保存读回已覆盖的新结论。HTTP失败/缓存混版/缺文件用确定性响应；平台提升/权限用mock。H只调用隔离原版fetch/preview读取源，不调用保存价格接口；先记录模型/插件/工具与options基线，结束读回证明无配置写入。使用独立测试实例或进程，不复用或修改仍运行的I夹具；可按本次开发授权准备独立本地测试资源，不触碰现有I夹具。本地HTTP连通性须从原版运行环境验证，不能默认容器内localhost就是宿主。原I仍只按获准配置导入读回范围解释。真实Pages部署/公开GET、运营目标应用和消费测试分别另获执行授权，不算已通过。H及三票粒度已随具体方案获准；票按前置关系开工，不需再次确认相同测试边界。

## v1.3 PUB-AC-02技术事实修正（2026-11-17）

本次**保留PUB-AC-02编号但修订其原文**；不声称旧AC原文未变。v1.2及以前“错误envelope由原版拒绝/去掉success由原版报错”过度概括已纠正，其余PUB-AC编号与定义保持。此为固定原版能力事实修正，不改变业务范围、不再访谈，不改new-api核心/升级，也不加业务代理或新应用器。

Planner亲自核对固定rc50 `f2aa91232ed3e5878a614762ace6736a2b74257f:controller/ratio_sync.go`：L428—430的`!body.Success`返回`Err: body.Message`；L585起仅`r.Err != ""`标error。因此缺success或success=false且message缺失/为空时，Err为空可能被聚合为test_results success，输出没有可用所选价格（隔离单源负例可为prices={}），并非一定标error。顶层success或test_results success都不证明数据齐全。
