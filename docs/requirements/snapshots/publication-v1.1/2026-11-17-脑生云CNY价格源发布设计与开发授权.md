## S/H验收边界

S沿用固定输入→固定包/schema/语义diff/完整性检查。唯一新增H是本地静态HTTP→独立隔离固定rc50原生fetch/preview→比较所选模型字段及失败结果。H不调用保存价格接口，不调用供应商，不复用或修改仍运行的I夹具。平台提升/权限分支用确定性mock；国内可达性不由本地H推出。

| 验证场景 | 预期结果/证据 |
|---|---|
| 同输入/选择/适配器重建 | releaseId及输出字节一致，旧artifact保持，模型mode/expr预览一致 |
| 错envelope、缺所选字段、不可表达条目 | success缺失/false由原版fetch拒绝；缺字段/无资料/不可表达由发布侧拒绝，不能依赖原版宽松解析 |
| 缺文件、错字节、混版本、覆盖固定版本 | 完整包校验或覆写拒绝，原有效版本不变 |
| 136参考与其他计数单位 | 原行保留，未选与不可表达原因区分，partial及差5可见 |
| 提升A到B、回退A、并发/重复请求 | 确认绑定版本/hash/diff；同一稳定入口的变更串行；重复请求先核对结果，不重复盲提升 |
| 提交前失败、提交后超时、缓存混版 | 分别保留旧入口、unknown后读回、按固定URL/hash识别并停止；不承诺全球跨请求原子 |
| H结束 | fetch/preview请求记录与模型/插件/工具/options基线读回一致，无配置写入或供应商请求 |

报告绑定固定实现commit和独立审查；旧I保存/恢复PASS不代替新H。上述是已获准的验收设计，尚未运行。

## 已批准的具体设计：入口与独立接入

以下为同一Pages站点内的逻辑路径，不是已存在URL；具体命名由实现确定。

| 入口/内容 | 谁消费、如何使用 | 边界 |
|---|---|---|
| 固定版本目录与manifest/inventory | 审阅者/运营按releaseId获取固定包，核对来源、选择、排除项及实际输出hash | 历史内容拒绝覆盖；manifest自身hash放外部回执/指针，避免循环 |
| 固定版本模型JSON | rc50原生fetch/preview使用完整Endpoint，响应success:true/data及模型字段 | 推荐在确认和应用期间使用此固定URL；不读取插件/工具配置 |
| 稳定发现指针 | 人或支持它的下载工具发现当前releaseId和固定版本链接 | rc50不认识此协议，不能把指针当倍率源 |
| 稳定模型JSON | 需要稳定模型源地址的消费方读取当前提升版本 | 与指针同部署快照生成；缓存可能造成不同请求跨版本，严格绑定必须使用固定URL/hash |
| 同版插件与工具文件 | 运营按包内说明分别走原生配置路径 | 插件版本化model_pricing；工具每千次单位、fresh全表合并与独占；无跨分区全局原子 |

源回退只把稳定入口提升到旧已验版本；不恢复实例配置、不重算账单。真实配置/调用验收仍走#10/#11相应目标及新意图，源下载成功不等于配置/消费/可售。

## 已批准的具体设计：权限与发布状态

| 阶段 | 设计约束 | 执行边界 |
|---|---|---|
| 核价/候选检查 | 人工PR审阅；候选CI保留contents:read，无发布凭据；构建不刷新核价日期 | D3方式已定，开发已获准 |
| 发布准备 | 独立workflow_dispatch候选设计；输入绑定releaseId/hash/确认记录；从已审核固定内容生成完整快照 | 设计已获准；仅输出非启用候选 |
| 部署权限 | 仅部署job授予pages:write、id-token:write；contents:read按实际读取需要保留；不默认增加contents:write | 设计已获准；不改真实设置 |
| 执行门禁 | 受保护environment及获准分支/固定版本；新动作逐个固定完整SHA并审查许可；现有三action白名单不自动放宽 | 具体SHA由实现审查，真实许可变化另授权 |
| 单入口状态变更 | 提升与回退串行，检查期望旧版本，确认后内容变化则拒绝；提交前失败保留旧入口 | 本地/mock演练 |
| 提交后结果不明 | unknown，不盲重发；读回固定身份后确定成功/失败，再按需要准备新回退确认 | 不声称所有失败均未提升 |

不继承上游push/schedule发布，不引入cron或外部托管。若environment能力或权限与设计不符，明确报告缺口，不静默弱化批准门禁。

## 开发关闭后的独立发布门禁

即使三票全部关闭，仍需另呈：精确首发模型/插件/工具选择及未覆盖原因、固定候选和release/hash、语义diff、当次发布确认、最小权限及动作审查结果。获准后才可开通/启用/部署，并验证实际公开读取与运营网络可达性；未知结果不报发布成功。运营目标写入、恢复和真实调用继续各自确认。长期维护频率/SLA尚未决定，不强加为当前开发阻塞。

## v1.1 用户效果澄清（2026-11-17）

用户已明确要求运营全程在new-api现有页面完成“配置源地址→拉取→预览→应用”，不需要命令行或手工API；[确认来源及缺口记录#22](https://github.com/naoshengyun/llm-metadata/issues/22)。这是实际使用效果要求，PUB-AC-08文档条件不再足以代表完整运营交付。原PUB-AC-01—10不改义，追加PUB-AC-11。

固定原版代码已有模型页面链路，但源URL只存组件内存，刷新/关闭同步窗口后丢失，仍借用上游预设行名称。持久化和独立名称并未被用户明确要求，需结合已证实限制确认可接受操作方式，不重新询问是否要页面。详见[固定页面能力证据](2026-11-17-脑生云CNY价格源原版页面能力核查.md)。不改new-api核心、不升级、不新增后台约束保持；不把CLI包装当满足，不扩大为三分区单URL自动应用。

T01/#19保持ready；T02/#20暂needs-info，页面适配及效果证据未闭环，不能凭HTTP/文档关闭；T03/#21纯发布机制不增加UI AC、不降级，但原有包交付依赖仍在。父Spec标记部分待澄清，不撤销独立格式开发。实际页面保存、现I夹具操作、部署和供应商调用仍未授权；本轮仅静态源码核查。
