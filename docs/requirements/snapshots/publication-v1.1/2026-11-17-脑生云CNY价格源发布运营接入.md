# CNY价格源发布运营接入 v1.1

## 维护来源与开发授权

本文件是Planner维护的Obsidian正式正文v1.0；仓库仅存字节一致的固定快照及来源索引，不维护第二份活正文。新增发布范围独立于原Spec/Tickets v0.12；原AC-01—30及历史T1—T7不改。

依据[开发方案批准记录（#17）](https://github.com/naoshengyun/llm-metadata/issues/17)：原Planner线程向用户展示固定de10ec0的A三票/S-H及B发布设计后，用户明确“继续下一步。”宿主核实转交批准按该开发方案落地；不重复同义审批。D1 Pages、D2分批并明确未覆盖、D3人工核价PR及手动发布分别见[#14](https://github.com/naoshengyun/llm-metadata/issues/14)、[#15](https://github.com/naoshengyun/llm-metadata/issues/15)、[#16](https://github.com/naoshengyun/llm-metadata/issues/16)。

**已批准本地开发、测试和候选配置设计；未批准任何真实发布执行。** 不开通Pages、不变更仓库权限、不启用workflow/部署，不批准精确首发selection、实例写入、供应商调用或fixture清理。未来运营条件不阻塞本地开发；常规实现/seam细节由Planner与Dev决定，不独设重复用户审批。正式交Dev由原Planner线程负责。

1. 发布后由维护者给出稳定发现入口、固定releaseId/manifest/模型源URL、plugin/tool文件及校验值。运营先读取coverage/selection/excluded、原价日期和partial标记；下载/发布成功不等于实例已应用或可售。
2. 固定目标rc50、USDExchangeRate=1、QuotaPerUnit500000；只读保存选中价格和未选键/版本/工具全表/有效组。原始USD×7已经在源内完成，不再乘7；组倍率由运营独立配置，不写入价格源。临时I夹具当前恢复为7.3，不是本次新的CNY应用目标。
3. 模型（现有页面候选路径，静态核实/运行待证）：具备原版SUPER_ADMIN/RootAuth的运营身份进入 `/system-settings/billing/model-pricing` → `Upstream price sync`，或 `/models/metadata` → `Sync pricing`；`Select price sources`内官方预设行已有custom输入，可整段替换为获选固定版本模型JSON完整URL，`Confirm Selection`拉取，逐模型选源，保持原价不再次换汇，`Apply Sync`预览差异，`Confirm Changes`才保存。禁止将本操作说明视为本次执行授权；当前不得点击保存。URL仅组件内存，刷新/关闭同步窗口后重填，预设名称/Official徽标不随URL改变；是否接受这些限制待原线程接续。接口请求是页面内部机制，运营不得被要求手调API作为替代。
4. 插件：从同一release读取指定model→plugin→expression，核对已有schema/profile，对应现有Model prices→模型编辑sheet/插件编辑器，页面保存内部使用版本化model_pricing；当前仅静态核对，完整页面效果仍需证据，不要求运营手调接口；模型源同步成功不能替代此步。
5. 工具：同release中每千次单位的tool表，现有Tool prices页有visual/JSON编辑和Save tool prices，内部为全表PUT；其页面不等于已有适配器的fresh合并实现，实际应用前仍需fresh基线和独占/读回边界；没有CAS，不自动与模型/插件合成全局原子。无独占则不应用该分区并报告部分状态。
6. 本次发布执行、目标实例写入和恢复意图均需各自明确确认；目标/候选/diff改变则重呈。冲突不强盖，超时先读回，unknown不报成功。源版本回退只改变源入口；实例恢复须新确认、fresh版本及工具独占，保留未选键，不重算旧账单。
7. 接入记录分别标识模型/插件/工具：下载已校验、配置已应用、调用/usage、扣费/账单、可售批准。后三项等待真实业务目标、渠道/alias/协议/schema与测试预算；不要求全136才能开始发布开发，不把配置I当真实O。

## 交接记录与未通过时的去向

| 阶段 | 必留证据 | 未满足时 |
|---|---|---|
| 发布准备 | 精确selection及排除原因、来源日期、固定release/hash、审阅与发布意图 | 不提升稳定入口；返回发布维护者 |
| 源下载 | 固定URL、实际字节hash、manifest及同版分区清单 | 不进入应用确认；稳定指针不是完整性保证 |
| 目标预检/预览 | 目标/原版/币种与配额、fresh版本、原配置基线、所选差异 | 回到真实业务输入记录#10补足；不得套用旧I目标 |
| 应用与恢复 | 分区逐项状态、实际确认者/原消息、fresh身份、读回及未选项保持 | 按#11新意图处理冲突/unknown；不重放旧确认 |
| 调用/账单/可售 | 获选通路与预算、usage/扣费账单证据、运营结论 | 记录未验收，不阻止独立价源开发或称全量可售 |

上述是开发交付的接入模板，不是要求当前填写渠道、密钥或实际调用。长期运营责任人、维护频率及可达性目标留待决策，不由开发默认承诺。


人工核价PR→审阅固定候选→手动发布指定版本已确认；首次实际发布时另确认具体名单/版本及执行意图。国内可达性须在获准发布后验证；不从本地H通过推导公网或可售成功。

## v1.1 用户效果澄清（2026-11-17）

用户已明确要求运营全程在new-api现有页面完成“配置源地址→拉取→预览→应用”，不需要命令行或手工API；[确认来源及缺口记录#22](https://github.com/naoshengyun/llm-metadata/issues/22)。这是实际使用效果要求，PUB-AC-08文档条件不再足以代表完整运营交付。原PUB-AC-01—10不改义，追加PUB-AC-11。

固定原版代码已有模型页面链路，但源URL只存组件内存，刷新/关闭同步窗口后丢失，仍借用上游预设行名称。持久化和独立名称并未被用户明确要求，需结合已证实限制确认可接受操作方式，不重新询问是否要页面。详见[固定页面能力证据](2026-11-17-脑生云CNY价格源原版页面能力核查.md)。不改new-api核心、不升级、不新增后台约束保持；不把CLI包装当满足，不扩大为三分区单URL自动应用。

T01/#19保持ready；T02/#20暂needs-info，页面适配及效果证据未闭环，不能凭HTTP/文档关闭；T03/#21纯发布机制不增加UI AC、不降级，但原有包交付依赖仍在。父Spec标记部分待澄清，不撤销独立格式开发。实际页面保存、现I夹具操作、部署和供应商调用仍未授权；本轮仅静态源码核查。
