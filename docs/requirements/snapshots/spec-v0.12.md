# 统一CNY价格源专项Spec（范围收敛稿）

本次范围以用户最新纠正为准：开发负责**官方价目导入/维护 → CNY基础价 → 固定产物 → 官方原版new-api应用读回**。官方/第三方接入选择、账号/渠道/别名映射、分组倍率及生产启用由运营配置；第三方采购成本/合同/账单不决定官方对客基准。复用已有计费与倍率机制，不新造倍率管理、供应商转发或任务恢复系统。

用户已批准按既定7票交Dev进行本次开发；Dev已正式确认接收并完整阅读Spec/T1—T7，规划交接完成；实现状态仍未证开工。远程建仓/fork、部署、生产改价仍未包含。本任务不重复落票或派发；历史扩大解释已撤回，证据保存在来源归档。

## 1. 目标、范围与职责

| 归属 | 内容 |
|---|---|
| 本专项开发 | 复用llm-metadata加载/覆盖/表达式；自有官方报价与币种政策；原始数据完整性；必要价格字段适配；上游同步保护；固定产物、差异、原生导入与读回 |
| 运营配置/上线 | 官方或第三方采购线路、账号/渠道、实际上游与别名映射、适用官方价目条目、分组倍率；具体人员/时限、生产目标和启用授权 |
| 范围外依赖/风险 | 通用异步404、提交丢ID、退款后迟到恢复、供应商账务核对、私有协议适配、存储生命周期meter等网关运行能力；不得在价格源票中重建 |

全平台、文本、图片、视频的官方价格源范围保留，不退回七款。18平台/136配置是覆盖参考，用户报告141与明细136差5仅资料注记；缺5不阻止开发、不补造、不催生产导出。官方model ID可作为价格目录身份；别名由运营映射消费此目录，不要求先证明实际采购线路。

目录键建议为`官方供应商 + 官方model ID + 官方价目地域/服务档 + 原始币种 + 计量形状/版本`，其中地域/服务档来自官方价目，不从私有线路推断。同名不同官方价目保持独立；导出时由运营选定条目绑定原生计费模型名。不能用上游聚合优先级静默吞掉差异。136行协议参考不去重，但不要求逐行生产映射闭合才写生成器。

## 2. 已确认硬约束

- 国产适用原始CNY保持；国外原始USD固定×7一次。禁止逆算models.dev已舍入USD，禁止将美元ratio成品整体再乘7。
- 站内`USDExchangeRate=1`、`QuotaPerUnit=500000`；套餐/分组倍率独立，由运营配置。开发测试只把倍率作为原生集成输入，不做新配置界面。
- 官方原版new-api，核查基线rc.50 `f2aa91232ed3e5878a614762ace6736a2b74257f`；不改核心、不加业务代理/第二套扣费、不默许升级或扩插件。
- 同一次图片/视频任务沿用原生提交价格快照，合法新尝试取新价；文本实时改价边界保持。未知先核实后结算是业务方向，但通用恢复缺口不在本次价格源关键路径，未宣称已解决。
- 已确认一个fork、main原样跟上游、naoshengyun业务分支、更新形成PR、校验后合入、价格发布另确认。具体默认分支、目录、workflow细节为实现建议；owner/托管稍后定，不阻塞本地夹具与设计。

## 3. 公开输入输出契约（最小建议）

输入：固定的llm-metadata源码/数据快照；自有原始官方报价记录；币种政策；官方条目选择；目标固定原版能力描述（可用源码导出的静态schema夹具）。报价至少含官方ID、来源URL/核对日期、币种、每个适用收费项金额/单位/阈值/TTL/条件。每项明确有价、官方免费或不适用，不能以缺失当零。

公开生成入口接收上述输入，输出：

1. CNY基础价与来源清单（原始价不覆写为CNY，以便追溯单次转换）。
2. 原生可接受的模型价格包：优先复用`billing_mode/billing_expr`及已有同步形状。
3. 需要时独立生成原生**已有**任务插件价格变体、工具价格配置包；不新增插件或计量器。
4. 每条官方记录的`ready / missing-source / incomplete / unsupported-shape`诊断，含具体字段、原因与目标能力。它们是价格数据处理状态，不是调用/可售状态。
5. 固定产物manifest及语义diff：源码SHA、数据/报价/政策/产物哈希，价格变更与描述/构建时间变化分开。

有缺失或不支持项时阻止**该项新价格**进入可应用包，绝不漏字段后报成功；完整包状态必须显示排除项。可用合成夹具完成缺字段拒绝行为开发，不能以尚未维护齐所有真实价目阻止生成器开工；全量官方价格覆盖目标仍保留。

## 4. 复用与最小适配边界

| 形状 | 开发方式 | 必须保留的判定 |
|---|---|---|
| Token/缓存/TTL/阶梯 | 复用上游生成器及原生表达式，覆盖先于过滤聚合，cost完整替换 | 金额换算不改阈值；不同协议真实usage属于后续集成，不妨碍价目/表达式夹具验证 |
| 图像Token/按张 | 能复用per_image/fixed×image_count就复用；缺失模态分项时在自有价格生成适配层增加显式字段映射 | 不把图像全部套Token；图文输入/输出/缓存价分离，单位不能丢；不改原生计费引擎 |
| 任务视频/图片 | 按固定原生插件usage schema生成价格表达式/变体，输出一次请求CNY金额；视频Token项需显式/1M | 不新增supplier协议或插件；schema缺字段则unsupported，不假定可按价格配置解决运行能力 |
| 工具独立费 | 只适配原生已有工具键与单位；与模型包分别声明、确认和应用读回 | 不从模型表达式推断已包含，不补开发新的次数采集；缺原生meter的收费形状显式不支持 |
| 存储/日历等条件 | 只有官方条件与原生输入能完整表达时生成 | 无token-hour输入、供应商专有状态或缺原始官方信息则显式报告，不用平均系数/二扣补齐 |

官方价目地域/服务档与采购价不同；运营选择标准/其它官方条目作为配置输入即可。价格来源缺原始CNY、混币、单位不明仍必须拒绝，用户纠正没有取消这些数据门禁。

## 5. 固定产物与应用

复用原生GET/PATCH `/api/option/model_pricing`与expected_version；模型包可继续走已有同步/预览流程。必要的插件变体/工具价用其原生配置接口，不能声称普通ratio_config已经覆盖所有字段。工具价单位按原生每千次口径转换。

最小受控动作是查看差异、明确选择固定产物/目标、调用原生应用、读回比较并留记录；优先沿用v1.2受控入口/身份，不新造独立报价后台或倍率管理。接口接受运行时授权身份和人工确认标记；不把未定姓名、独立双人制度、2工作日宽限等旧建议变成开发前置或已批准政策。

仅修改本次选定官方价格字段；全表型原生配置须读回合并并保留未选键，不写账号/渠道映射或分组倍率。应用冲突重新读回，不能强覆盖；超时先读配置，部分成功逐项呈现，不自动抹平未知。恢复价格配置也须新意图/确认，且不重算历史账单。模型/插件/工具跨配置全局原子性不承诺。验证、确认、应用使用同一固定产物，不重拉后冒用旧确认。

## 6. 当前开发Done与最低测试

本地即可：公开入口的CNY不变、USD单次×7、完整收费形状、单位/阈值、unsupported与缺字段拒绝、同名保留；固定输入构建/语义差异；同步合并夹具保护自有内容；原生接口形状、版本冲突、部分应用及读回模拟。后续可在授权隔离原版实例验证真实导入保存读回，仍不需要生产账号或供应商账单。

本次价格源开发Done：已承诺支持的形状在公开入口与原生配置边界验证正确；其余明确诊断而非漏价；产物身份与导入读回可核对。**不是136条真实调用/计费/可售全通过，也不是全部异步风险已解决。** 价格源与媒体字段适配仍有具体开发工作，不把“导入已有计费”说成全形状已完成。
