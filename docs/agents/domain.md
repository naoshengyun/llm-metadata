# Domain docs

This repository uses a single-context layout:

- GLOSSARY.md at the repository root.
- docs/adr/ for architectural decisions.

Before exploring code, read the glossary if present and ADRs relevant to the area.
If a GLOSSARY-MAP.md exists later, follow its links for the relevant contexts.

Missing glossary or ADR files do not block work. Proceed silently.
Create them through domain modeling when terminology or decisions are resolved.

Use established glossary terms in code, tests, issues and explanations.
When a proposal conflicts with an ADR, identify the conflict explicitly before
changing the decision.
