# PUB-T03：受控稳定入口提升与回退

Status: draft-awaiting-user

**What to build:** 审阅者确认固定版本后，在演练中手动提升发现指针与模型消费入口；失败保持旧入口，手动回退复用旧不可变版本，并给运营可追溯回执。

**Blocked by:** PUB-T02；用户确认PUB-D1/D3/D4与发布格式。首版具体选择和真正部署/启用另需明确确认。

关闭条件：PUB-AC-05、PUB-AC-06、PUB-AC-07、PUB-AC-09、PUB-AC-10；本地HTTP/平台mock验证同部署快照一致、缓存跨版本检查、失败不提升、回退身份、重复执行和权限不足失败；只手动、固定SHA动作/最小权限声明及独立QA审查通过。候选CI继续只读，继承workflow不被启用，无cron/自动上游合入；稳定入口回退不写实例。真实Pages开通/Actions新许可/部署试跑及公开下载回执在另外明确获准后验收，不在本票关闭时冒称完成。

## Seam 与可独立演示的路径

复用S/H与确定性平台mock：审阅者针对release/hash/diff确认→准备完整部署快照→本地提升发现指针和模型源→读回；再确认回退到历史版本→读回。托管实现选择须先获批，mock通过不能当作真实Pages权限或可达性证据。

演示：版本A提升至B、回退A，历史固定文件不变；无确认、权限不足、缺分区、确认后内容变化、重复执行均有确定结果。提交前失败保留旧入口；平台提交后回执超时记unknown并先读回，不能笼统承诺所有失败都未提升。跨请求缓存读到A/B混合时，通过固定URL/hash识别并停止，不宣称公网原子读。
